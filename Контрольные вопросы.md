# Контрольные вопросы

## 1. Для чего предназначены модульные тесты?

Они проверяют отдельные части программы: метод, класс или функцию. Тест сравнивает фактический результат с ожидаемым и помогает заметить ошибку после изменений. В этой работе тесты интеграционные: они отправляют HTTP-запросы к настоящему Petstore.

## 2. Чем отличается NUnit от xUnit?

В NUnit тест помечается [Test], подготовка выполняется в [SetUp], очистка — в [TearDown]. В xUnit обычный тест помечается [Fact], параметризованный — [Theory]. Для каждого теста xUnit создаёт новый экземпляр класса; асинхронную подготовку и очистку в использованной версии 2.9.3 задаёт IAsyncLifetime.

## 3. Что такое параметризация тестов?

Это запуск одного метода с несколькими наборами входных данных. Здесь bool negative выбирает позитивный или негативный сценарий. В xUnit используются [Theory] и [InlineData(false/true)], в NUnit — [TestCase(false/true)]. Каждый набор считается отдельным тестом.

## 4. Для чего используются фикстуры?

Для подготовки данных и ресурсов перед тестом и очистки после него. Здесь каждому тесту выделяется клиент и собственные записи. После проверки свои записи удаляются. Уникальные имена пользователей и ID питомцев позволяют запускать тесты независимо от порядка.

## 5. Зачем тестировать работу репозиториев?

Репозиторий отвечает за сохранение и чтение данных. Проверки позволяют найти ошибки фильтрации, связи между записями, нарушения ограничений и потерю данных. После сохранения полезно прочитать запись заново и проверить поля. Локальные репозитории и база данных в этой работе не создавались: проверяются операции удалённого API.

## 6. Как выполняется запуск тестов в .NET? В какой IDE работаете?

IDE для C# — JetBrains Rider. В этой работе сборка и запуск выполнены из терминала через .NET CLI. Из папки проекта команда dotnet test восстанавливает пакеты, собирает проект и запускает тесты. После готовой сборки использована dotnet test --no-build --no-restore с записью результата в TRX. В Rider тесты также можно запускать из окна Unit Tests.

## 7. Что общего между pytest и xUnit?

Они автоматически находят и запускают тесты, показывают ошибки проверок, поддерживают параметризацию и подготовку данных. Оба можно запускать из командной строки и CI. pytest работает с Python, xUnit — с языками .NET.

## 8. В чём преимущества pytest?

Для простого теста достаточно функции test_ и assert. Фикстуры передаются аргументами, могут зависеть друг от друга и иметь разную область действия. Параметризация задаётся одним декоратором. Для HTTP, асинхронных тестов, покрытия и отчётов есть библиотеки и плагины.

## 9. Для каких задач может быть интересен Expecto?

Для проектов на F#, где удобно описывать тесты функциями и объединять их в списки. Он подходит для проверки чистых функций, свойств алгоритмов и асинхронного кода. Можно использовать FsCheck для генерации входных данных и проверки общих свойств.
